# Деплой бота: бесплатный хостинг с быстрым деплоем

Бот работает на **long polling** (`app.run_polling()`), поэтому хостингу не нужен
публичный URL/SSL — достаточно, чтобы процесс крутился 24/7. Это сильно упрощает
выбор: подойдёт любой хостинг, который умеет запускать python-скрипт как воркер.

## Сравнение бесплатных вариантов

| Сервис | Бесплатно | Деплой | «Быстрый редеплой» | Минусы |
|---|---|---|---|---|
| **Render.com** (Background Worker) | ✅ 512 MB | из Git-репо | автодеплой при `git push` | на free-плане worker останавливается, когда проект «засыпает»; для бота лучше следить за активностью |
| **Railway** | только пробные $5 | из Git / `railway up` | CLI за секунды | free tier ограничен |
| **Fly.io** | фактически кредит ~$5 | `fly deploy` | очень быстрый (~30 сек) | нужен аккаунт с картой |
| **PythonAnywhere** | ✅ | git + консоль | вручную (kill + start) | **free: нет исходящего доступа к API Telegram** (белый список доменов) → бот там не заработает |
| VPS (Timeweb/Selectel ~200₽/мес) | ❌ платно | systemd | мгновенно | деньги |

### Почему PythonAnywhere — плохой вариант именно для этого бота
На бесплатном тарифе исходящие сетевые запросы разрешены **только к доменам из
белого списка**, и `api.telegram.org` в нём нет. Бот просто не сможет ходить за
обновлениями и картинками (а `link_parser` тянет страницы со всего интернета).
Плюса ради: там удобно быстро гонять код в консоли, но не держать polling-бота.

### Рекомендация: Render Background Worker
1. Заведите репозиторий на GitHub с этим кодом (секреты — только через env!).
2. Render → **New → Background Worker** → подключите репозиторий.
3. Environment: Python 3.11+.
4. Build command: `pip install -r requirements.txt`
5. Start command: `python bot.py`
6. Add Environment Variables:
   - `BOT_TOKEN` = токен от @BotFather
   - `CHANNEL_ID` = канал по умолчанию, например `-1004447835579`
   - `CHAT_CHANNEL_MAP` = привязка чат→канал (см. ниже)
7. **Auto-Deploy: On branch push** — теперь деплой = `git push`, занимает ~1 минуту.

Локально перед пушем можно проверить так:
```bash
BOT_TOKEN=... CHANNEL_ID=-1004447835579 \
CHAT_CHANNEL_MAP="-1003743298448:-1004447835579" \
python bot.py
```

## Твои ID (что уже известно)
- Чат старого канала: `-1003743298448`
- Новый приватный канал: `-1004447835579`
- ID **чата** нового приватного канала пока неизвестен — получи его тем же способом
  (перешли любое сообщение из того чата боту и посмотри `chat.id`, или временно
  запусти `python whoami.py` и напиши боту в этот чат).

Пример конфигурации после получения всех ID:
```
CHANNEL_ID=-1004447835579
CHAT_CHANNEL_MAP=-1003743298448:-1004447835579,-100XXXXXXXXXX:-1004447835579
```
(первая пара — старый чат постит в новый канал; вторая — чат нового канала
постит в новый канал)

## Быстрые альтернативы с ещё более удобным деплоем
- **GitHub Actions** (не хостинг, но бесплатно): workflow c `on: push` запускает
  бота на раннере — минус: лимит 2000 минут/мес и job убивают через 6 часов. Годится
  для коротких тестов, не для постоянной работы.
- **Docker + Railway/Fly**: `fly deploy` поднимает образ за ~30 секунд — самый
  шустрый цикл «изменил → в проде».
- Если хочется совсем без регистрации заграничных сервисов: самый дешёвый VPS и
  `systemctl restart bot` — деплой мгновенный.
