# Деплой: бесплатный хостинг и быстрый цикл «изменил → в проде»

## Коротко
- **PythonAnywhere (free) — не подходит.** Там исходящая сеть разрешена только
  на домены из белого списка, а `api.telegram.org` в нём нет, поэтому бот не
  сможет ни получить обновления, ни опубликовать пост. Плюс процесс
  long-polling приходится перезапускать руками.
- **Render.com (Background Worker, free) — лучший вариант для теста**: git push
  = автодеплой, все настройки через Environment Variables.
- Fly.io / Railway — быстрее по времени деплоя, но требуют привязанную карту.

## Настройки (Environment Variables на Render)
| Переменная      | Пример                       | Зачем |
|-----------------|------------------------------|-------|
| `BOT_TOKEN`     | `1234567890:AAAA...`         | токен от @BotFather |
| `CHAT_ID`       | `-1003743298448`             | чат, откуда берём ссылки |
| `CHANNEL_ID`    | `-1004447835579`             | канал, куда публикуем |
| `KEEP_ALIVE_MIN`| `10`                         | *опционально*, интервал «прогревающего» пинга (`0` — выключить) |

## Пошаговый деплой на Render
1. Запуши это репо на GitHub (секретный `config.py` остаётся только локально —
   он в `.gitignore`).
2. render.com → **New +** → **Background Worker** → подключи репо.
3. Start command: `python bot.py` (Render сам поставит зависимости из
   `requirements.txt`; если ругается на Python — укажи `runtime.txt` со
   значением вида `3.12`).
4. Add Environment Variables — таблица выше.
5. Создай сервис, затем в Settings включи **Auto-Deploy: On commit**.
   Дальше любой `git push` = новый деплой за ~1 минуту.

Логи — во вкладке Logs, там же видно `Бот стартует. чат=... канал=...`.

## Про «засыпание» на бесплатных тарифах
Что происходит на free-плане Render **Web Service**: если за 15 минут не было
ни одного входящего HTTP-запроса к публичному URL сервиса, контейнер
останавливается. Просыпается он по следующему запросу (несколько секунд), но
боту входящие запросы не нужны — он сам ходит за апдейтами, поэтому web-URL
никто не трогает и сервис заснул бы навсегда.

Нюансы, которые важно понимать честно:
- **Background Worker формально не должен спать** — Render усыпляет именно
  бесплатные *web* сервисы. На практике free-воркеры тоже периодически
  перезапускаются/приостанавливаются, а сам free-ресурс (750 instance-hours)
  рассчитан как раз на «спящие» веб-сервисы.
- Классический трюк «curl свой же URL каждые 5 минут» тут **не работает**:
  внутренний трафик (ping-сервисы типа UptimeRobot к worker'у без URL) не
  считается активностью.
- Поэтому в `bot.py` есть лёгкий фоновый тик `keep_awake()` раз в
  `KEEP_ALIVE_MIN` минут. Он поддерживает процесс занятым (long polling и так
  держит соединение с Telegram, так что обычно достаточно его); при желании
  отключается `KEEP_ALIVE_MIN=0`. Это страховка, а не гарантия: если Render всё
  же решит остановить free-процесс, он его остановит.

Если гарантированно «без снов» и бесплатно хочется:
- **Fly.io free allowance** (до 3 VM) или **Railway trial** — процессы живут
  постоянно; минус — нужна карта.
- **Свой VPS / домашняя машина / WSL** — для тестов приватного канала самый
  простой путь: `python bot.py` и всё работает, деплоя нет вообще.
- Платный тариф Render ($1/mo Starter) убирает ограничения полностью.
